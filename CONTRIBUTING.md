# Contributing to ios-orb

Thanks for considering a contribution to `kevnm67/ios-orb`. This repo is a
CircleCI orb authored in **unpacked form** — read
[`CLAUDE.md`](CLAUDE.md) first for the full architecture; this file covers
the day-to-day contributor workflow.

## Prerequisites

```bash
make setup
```

Installs `bats-core`, `shellcheck`, `pre-commit`, and the `circleci` CLI via
Homebrew, then installs the pre-commit git hook.

## Branching and commits

- Branch from fresh `main`: `git fetch origin main && git checkout -b
    {type}/{TICKET-ID}-{description}` (types: `feat`, `fix`, `docs`, `style`,
    `refactor`, `test`, `chore`).
- Commit format: `type(scope): description [TICKET-ID]` — e.g.
    `feat(commands): add upload_dsyms [IOS-ORB-V3]`.
- Reference the actual ticket ID (this project uses `IOS-ORB-V3`) in the
    branch name (no brackets) and in every commit / PR title (brackets).

## Where things live

| You want to... | Edit |
| --- | --- |
| Change a command, job, executor, or example | `src/commands/`, `src/jobs/`, `src/executors/`, `src/examples/` — **never** `src/ios.yml` or the root `orb.yml` (both are generated by `pack.sh`) |
| Add real shell logic | `src/scripts/*.sh` (orb steps, pulled in via `<< include() >>`) or `scripts/ci/*.sh` (repo CI) — never inline shell beyond a trivial one-liner |
| Add/update a test | `tests/scripts/<script>.bats` (mirrors `src/scripts/`), `tests/hooks/<hook>.bats` (mirrors `.claude/hooks/`), or `tests/ci/<script>.bats` (mirrors `scripts/ci/`, for scripts not covered by `run-script-tests.sh`) |
| Document a new/changed parameter | Both `README.md` **and** `src/README.md` — see `scripts/ci/check-readme-params.sh` |

## Naming rules (don't mix these up)

- Orb components — `src/commands|jobs|executors/*.yml` file names and every
    `parameters:` key — are **snake_case**. This is the one place snake_case
    wins: `orb-tools/review` **RC010** fails on a hyphen, and renaming a
    published component is a breaking change for consumers.
- Everything else CircleCI lets you choose (repo pipeline job/workflow
    names, cache-key prefixes, contexts, `scripts/ci/<verb>-<noun>.sh`,
    `.claude/agents|skills/*`) is **kebab-case**.
- `src/scripts/*.sh` are snake_case, matching the command they back
    (`swiftlint_run.sh` ↔ `swiftlint`).

## Local dev loop

```bash
make pack       # cd src && ./pack.sh — packs src/ into src/ios.yml + circleci orb validate
make validate   # pack + circleci config validate on both .circleci/*.yml
make test       # bats tests/scripts (add tests/hooks, tests/ci as needed — see below)
make coverage   # bats under kcov -> coverage/cobertura.xml (matches CI)
make hooks-test # bats tests/hooks
make lint       # pre-commit run --all-files
make shellcheck # shellcheck on every shell script in the repo
```

Also run directly when working on a specific suite:

```bash
bats tests/scripts tests/hooks tests/ci
./scripts/ci/check-readme-params.sh
circleci config validate .circleci/config.yml
```

`circleci config validate .circleci/test-deploy.yml` always reports
`"Cannot find a definition for command named ios-orb/…"` locally — that's
expected; `orb-tools/continue` injects the orb into that pipeline at CI
runtime, not during local validation.

## Docs stay in lockstep

`README.md`, `src/README.md` (parameter tables + "What's new"), `CLAUDE.md`,
`CHANGELOG.md` ("Unreleased" section), and the pinned version in
`src/examples/*.yml` change **in the same PR** as the YAML/script change they
describe — not as a follow-up. README fenced YAML blocks use 4-space
indentation (qlty's editorconfig-checker flags 2-space lines inside them);
any indented markdown line must indent by a multiple of 4 spaces.

## Claude Code project setup

If you're using Claude Code against this repo, `.claude/settings.json` wires
up hooks that:

- Block `git push` when `src/`/`tests/` have commits newer than the last
    verified `cd src && ./pack.sh` run (`check-verified.sh`).
- Deny any Edit/Write targeting the packed `src/ios.yml` or `orb.yml`
    (`block-packed-files.sh`) — edit the unpacked source instead.
- Automatically re-pack + validate whenever an unpacked orb source file
    changes, stamping the verification marker the push gate checks
    (`pack-validate.sh`).
- Remind (advisory only, never blocks) when `src/commands|jobs|executors`
    changed without a matching `README.md` / `src/README.md` edit
    (`readme-sync-check.sh`).

See `.claude/skills/` for guided workflows (`orb-add-command`,
`orb-param-sync`, `xcode-image-bump`, `orb-diagram-sync`, `orb-release`) and
`.claude/agents/` for specialist subagents
(`circleci-orb-author`, `bats-test-writer`, `orb-docs-syncer`).

## Opening a PR

1. Run every gate in [Local dev loop](#local-dev-loop) — all green before
    pushing.
2. Open the PR against `main`. CI runs `lint-pack` (lint, pack, `orb-tools/review`,
    shellcheck, script tests) then `test-deploy` (`command-test`,
    `fixture-test`, `spm-fixture-test`, `fastlane-fixture-test`).
3. Address every qlty finding — 0 findings is the merge bar, not "pre-existing
    is fine."
4. Squash-merge once green.

## Releasing

Releases are tag-triggered, not manual — see the `orb-release` skill or
`.claude/agents/circleci-orb-author.md` for the full pre-tag gate list and
verification steps. In short: merge to `main`, then `git tag vX.Y.Z && git
push origin vX.Y.Z`. CircleCI publishes the orb and
`.github/workflows/release-on-tag.yml` creates the GitHub Release — never run
`circleci orb publish` by hand.
